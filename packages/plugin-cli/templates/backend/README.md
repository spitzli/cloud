# __NAME__

An independent backend extension generated by `@spitzli/cli`.

This local integration fixture demonstrates a real `ctx.jobs.enqueue` call and an idempotent background handler. It is not a production-installed plugin. The host owns BullMQ, Redis credentials, authorization, scopes and dispatch.

## Develop

Install the released SDK dependency and build the generated project:

```sh
bun install --ignore-scripts
bun run build
spitzli-cloud plugin validate
```

When testing an unpublished SDK archive, temporarily merge this override into the
generated `package.json` before installation (replace the absolute path):

```json
{"overrides":{"@spitzli/plugin-sdk":"file:/absolute/path/spitzli-plugin-sdk-0.1.0.tgz"}}
```

The override also resolves the CLI's exact SDK dependency during local tarball tests.
Remove this local-only override when switching to the published version. For a
packed local CLI, invoke its `node_modules/.bin/spitzli-cloud` executable.

Run with `WEBDOCK_PLUGIN_HOST_URL`, a 32+ character `WEBDOCK_PLUGIN_RUNTIME_TOKEN`, and optionally `PORT` (8080). Default bind address is loopback. The Dockerfile explicitly sets `HOST=0.0.0.0` for container networking. The runtime token is a local fixture transport secret; production invocations must use the host's short-lived invocation transport.

`POST /webdock/actions` with `name: demo.enqueue`, `payload: {message: "hello"}` and an idempotency key schedules `demo.process`. It requires the runtime Bearer token plus `x-plugin-invocation` from the trusted host. The host dispatches the declared job via `/webdock/jobs`; the handler returns an uppercase message and SHA-256 without side effects. Repeated execution is safe.

## Pack (no publication)

The zero-digest image in `tabularium.json` is an authoring placeholder. Build/push your own image separately, then supply its real digest:

```sh
spitzli-cloud plugin pack --image ghcr.io/spitzli/my-extension@sha256:<actual-digest>
```

This writes identical `dist/tabularium.json` and `dist/__NAME__-universal.json`, plus a checksum lock. It does not upload a release, publish an image or install into a host. Runtime image availability and signed-registry admission remain separate gates.
