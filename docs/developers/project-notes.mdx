[Project Notes](https://github.com/spitzli/webdock-extension-project-notes) is an established protocol-v1 reference extension. Its signed `0.1.0-alpha.2` release and immutable assets remain preserved. It uses top-level `kind: "extension"` fields and the retained TypeScript SDK.

## Reference behavior

The example keeps project-scoped notes with optimistic document revisions and idempotent write receipts. Its legacy authoring fixture also demonstrates BullMQ reminders that mark notes due in the panel; it sends no email. This is historical fixture behavior, not a promise of interval scheduling in the native host.

The UI uses a sandboxed frame and host-owned message channel. Runtime tokens, provider keys and database credentials stay outside the frame. Host admission controls project access and capabilities.

## Data limits

The reference supports up to 100 notes, 100 characters per title and 5,000 characters per body within a 24 KiB total document. Reminder dates in the legacy fixture are limited to seven days ahead. Editing or deleting a note invalidates its previous reminder version.

Document reads return value and revision. Writes compare the expected revision and retain an operation receipt. Keep the same key when retrying unchanged input; changed input with a reused key or a stale revision fails instead of overwriting another edit.

## Develop or migrate

Follow the independent repository's README and pinned dependencies for that v1 release. Retained local fixtures do not establish production installation, customer activation or native runtime compatibility. Current native jobs reject interval scheduling; see [background jobs](/developers/plugin-jobs).

For a new native extension, start from [cloud-plugin-echo-demo](https://github.com/spitzli/cloud-plugin-echo-demo) and the [native SDK](https://github.com/spitzli/cloud-plugin-sdk). Preserve Project Notes' existing signed bytes; changing protocol numbers is not a migration. See [independent releases](/developers/plugin-releases).
