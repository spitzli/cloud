title: "Websites and content"
description: "Edit drafts, preview changes and publish an assigned website."
---

Open your assigned website in [Console](https://console.spitzli.cloud). Each connected website keeps its own CMS, schema and content. Access depends on current workspace membership and website grants.

<Steps>
  <Step title="Select the website">Check that you are in the correct workspace, then open the intended website.</Step>
  <Step title="Edit content">Select an available page or collection. The website's schema determines which fields and content types you can edit.</Step>
  <Step title="Preview the draft">Inspect your changes using the website's supported preview. A preview does not publish content.</Step>
  <Step title="Publish">Save and publish through the available controls, then check the public page.</Step>
</Steps>

If another editor saved a newer version, reload and reconcile the conflict before saving. Do not overwrite it just to dismiss the conflict.

## Canvas-enabled websites

Where the canvas integration is enabled, it supports text, images, shapes, buttons, layers, undo and desktop, tablet and mobile artboards. Responsive preview can show unsaved edits. Published content and homepage activation remain separate from draft editing.

## Add a website

Ask your operator to configure the website binding and permissions for an existing website. An inventory record alone does not install a CMS, create a database or grant sign-in access.

The optional [Managed CMS](/guides/managed-cms) flow can create an independent instance when explicitly activated and accepted for the project. Connecting an existing website retains its own content model; it does not add a general schema designer.

For implementation details, see [website integration](/developers/website-integration).
