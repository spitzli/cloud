---
title: "Applications and deployments"
description: "Inspect application health, change configuration and follow rollout operations."
---

Open the application's project in [Console](https://console.spitzli.cloud). Applications have their own configuration, runtime state, operations and logs. Hosting must be enabled and assigned before you can create or change a workload.

For a new workload, follow [Set up an application](/guides/project-setup).

## Check the application

Review its observed state, recent operation and expected endpoint. Use logs to investigate a startup or healthcheck failure. An accepted operation is still in progress until its result and runtime observation are available.

| State | Next step |
| --- | --- |
| Running or ready | Check application health and the expected endpoint |
| Change in progress | Follow the existing operation |
| Stopped | Use **Start application** when needed and permitted |
| Failed or needs review | Read the operation error and resolve the reported condition |

Where authorized, use **Stop application**, **Start application** or **Restart application**. Wait for the current operation before requesting another change. If the result is uncertain, use the existing request's retry or ask an operator to reconcile it.

## Configure the runtime

Use the application's available settings for its image, resources, healthcheck and environment. Keep secrets in private environment fields. An image must be pinned to an immutable digest supported by the assigned runtime.

Durable files belong on approved [persistent storage](/guides/storage), mounted at `/data` in the fixed-volume model. Process restarts retain that volume; the container's temporary filesystem is not durable storage.

Default public project addresses use `spitzli.site` where address allocation is enabled. Use the exact HTTPS address displayed in Console. A custom domain requires its own configuration and verification.

## Builds and publication

For explicitly activated repository sources, use [Git builds and deployments](/guides/git-deployments). Git self-service is not generally available. Build success confirms build output; publication and application readiness have separate states.

Redeploying a retained version does not restore application data or reverse migrations. Review compatibility before deploying an older image.

<Warning>Deleting an application and permanently purging its storage are separate operations. Review the current deletion preview and retained data before confirming either action.</Warning>

For customer-owned infrastructure, see [Bring your own accounts](/guides/byok). Connecting a provider does not automatically deploy an application.
